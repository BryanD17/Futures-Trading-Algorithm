## DECISIONS

1. **Scope vs ownership map.** The acceptance grep ("only EngineConfigLoader") and task 2
   ("classes that read properties in static initialisers ... BiasVoteEngine.install,
   IctLibConfig, ChartEngine, ConfluenceField, TradeProfile, … must read the loaded
   config") cannot be met without touching the property-read lines of files outside the
   CONTEXT list. I made one-line swaps only (`System.getProperty(...)` →
   `EngineConfig.current().getX(...)`), no logic change, and list every file below.
   The harness negative control (above) proves byte-identical behaviour.
2. **Live -D layer.** File/env/classpath layers load once (EngineFacade construction or
   first read); the -D layer is consulted at read time through the loader's reader so
   existing tests that `System.setProperty` after load keep working and -D stays highest.
   In production nothing sets system properties after boot, so the boot table IS the
   runtime config.
3. **Canonical names + aliases.** Appendix C names are canonical (`scalp.enabled`,
   `displacement.recentBars`, `bias.hysteresis`, `engine.symbol`, `setup.expiryBars`,
   `raid.minScore.scalp`, `session.allSessions`, ...); every legacy name is an alias, so
   the owner's `-Dstdvote.displacement.*` flags and every test's legacy key keep working.
   Within one layer the canonical name wins.
4. **Tests are hermetic.** The test task sets `engine.props=NONE` unless
   `-Pengine.props=<path>` is given; bootRun (like java -jar) reads
   `${user.home}/topstep-trading/engine.properties`. Parity is achieved by passing the
   same `-Pengine.props` (proved in §2 and §9).
5. **`session.gateMode=SCORING` is carried, not consumed.** The boot line says so
   ("consumer = Agent 02"). On this branch M3 behaves as on Main until Agent 02 lands.
6. **`bias.hysteresis=true` default** (task 3) changes cfg A's histogram as shown (grace
   holds setups; NEUTRAL deaths become "NEUTRAL beyond grace"). `bias.neutralGraceBars`
   stays 2 (Agent 03 owns re-parameterisation to 3).
7. **GateDecisionEvent publication.** Runners publish (a) one row per setup TRANSITION
   (state or `lastGateFailed` changed) from the candle path — not per bar, to keep the
   200-row ring meaningful; (b) one row per signal outcome through the single
   `releaseUnexecutedSignal` funnel + "SIGNAL received" + "APPROVED". Signal rows use the
   signal's BaseEvent stamp as `candleTime` (wall clock, D-01) — marked `AGENT-05`.
   `EngineTelemetry.sessionOf` mirrors the harness windows — marked `AGENT-02`.
8. **Strategy fail-fast.** `StdvOteFactory` throws `IllegalArgumentException` for
   non-{MNQ,MES,MGC} unless `strategy.legacyFallback=true`; `strategy.stdvOte=false`
   remains an explicit, logged rollback.
9. **MockConnector** static -D reads became per-instance EngineConfig reads (a test that
   set `sim.warmBoot=false` before class load otherwise poisoned later tests).
10. **Secrets** (`topstep.apiUrl/username/apiKey/accountId`) are masked `****` in the
    table and API.
11. `notify.discord.enabled` (PR #151 key, not read on Main) is registered and carried.
