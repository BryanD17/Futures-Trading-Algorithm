# A-05.1 — OPUS SUB-AGENT 05.1 (fixer): phase-aware setup expiry (starvation S2)

Branch `fix/agent-05.1-v5-phase-expiry` off Main `ac5e602`. Status: 🔄 READY-FOR-FABLE (not merged).

## Problem (S2, measured on Main ac5e602, cfg A, real tape)
One 60-minute hunt budget, counted from SWEEP_DONE (Agent 02, RC-03), covered
sweep -> displacement -> MSS -> retrace into OTE. 87 of the tape's post-sweep deaths were
`expired (60 bars after SWEEP_DONE without an entry)`, all 61 feed bars after the sweep:
39 in SWEEP_DONE, 19 in DISPLACED, 21 in MSS_CONFIRMED, 7 in OTE_ARMED, plus 1 IN_TRADE latch net.
The 21 MSS_CONFIRMED deaths were setups that were progressing normally and still waiting
for the retrace.

## Fix (R3: re-parameterised + corrected; no gate deleted)
New expiry anchor `PHASED` (SCORING default). Each post-sweep phase has its own budget, and
the budget resets on the forward state transition:

| phase | key | default |
|---|---|---|
| BIAS_SET / MANIP_DONE -> SWEEP_DONE | `setup.preSweepExpiryMinutes` (Agent 02, kept) | 480 min |
| SWEEP_DONE -> DISPLACED | `setup.expiry.sweepToDisplacement` | 60 min |
| DISPLACED -> MSS_CONFIRMED | `setup.expiry.displacementToMss` | 60 min |
| MSS_CONFIRMED -> OTE_ARMED | `setup.expiry.mssToOte` (a backstop; the OTE 1.0 invalidation is still the real gate) | 240 min |
| OTE_ARMED -> emit | `ote.windowBars` (Agent 04, runner, unchanged). The core applies no time budget here | 8 detector bars |
| IN_TRADE / MANAGING | pre-V5 latch-release net (unchanged) | 40 detector bars |

- `setup.expiryAnchor`: `PHASED | SWEEP_DONE_TOTAL | BIAS_SET`. The code default follows `session.gateMode`
  (SCORING -> PHASED, BLOCKING -> BIAS_SET, so BLOCKING A/B is unchanged). `SWEEP_DONE_TOTAL` is Agent 02's
  single budget (`setup.expiryMinutes` / `setup.expiryBars`), kept for A/B. The old value `SWEEP_DONE` is still
  accepted as an alias.
- Keys are registered in `EngineConfig.KEYS`. This also registers `setup.expiryAnchor`, `setup.expiryMinutes` and
  `setup.preSweepExpiryMinutes`, which Agent 02 read but never registered. The three phase budgets are in
  `engine-defaults.properties`. `grep -rn "System.getProperty" trading-engine/src/main` -> EngineConfigLoader only
  (0 other hits).
- Invalidation reason names the phase and the two numbers, e.g. `expired: MSS_CONFIRMED→OTE 241 > 240 min`.
  FunnelTelemetry groups these reasons by phase.
- Boot line: `expiry anchor=PHASED sweep→displacement=60 displacement→MSS=60 MSS→OTE=240 min (feed bars)
  OTE→emit=ote.windowBars preSweep=480 min`.

**Exact bar-level rule.** The runner's record* hooks advance the state after `core.onCandle`, on bar B
(so `barIndex == B` once onCandle has returned on that bar). The next onCandle sees the new state without
a stamp and sets `phaseAtBar = B`, then increments. After n more feed bars,
`elapsed = barIndex - phaseAtBar = n`. The phase survives while `elapsed <= budget`. It is INVALIDATED on the
first bar where `elapsed > budget`, which is the (budget+1)-th feed bar after the transition bar. This is the same
convention as Agent 02's `sweepAtBar`, so the legacy mode still dies at bar 61. When several states are crossed on
one bar, the clock is stamped once, for the state finally reached. States only move forward, so a stamp is never
reused.

Files: `strategy/session/SessionConfig.java`, `StdvOteStrategy.java` (lifecycle/expiry block only),
`StdvOteRunnerStrategy.java` (Agent 02 expiry-wiring lines in the ctor only; Agent 04's
tryRecordDisplacement / tryRecordMss / tryArmOte are untouched), `FunnelTelemetry.java` (normalise),
`EngineConfig.java` (KEYS), `engine-defaults.properties`, tests.
