### Exact reason: it was NOT the sizer

**The sizer was never called.** The 41 armed bars never reached `tryEmitOrder`. `OteSetupDriver.alarm()` returned `false` on every bar with the stall `impulse-no-pd-array-at-sweep`. The stall column of Fable's CSV already showed this (`OTE_ARMED:impulse-no-pd-array-at-sweep` on all 41 NY_AM rows). The harness label `OTE_ARMED-sizer-standdown-or-tier` was a guess made from `lastGateFailed == null`, and the alarm stall never reached `lastGateFailed`.

The 05.2 IMPULSE_LEG entry model looks for a PD array at the sweep, and found none:
- **Sweep OB.** `sweepOrderBlock` needs the sweep bar itself to close opposite, i.e. down for a long. The 10:06 bar is `o=30757.5 h=30783.0 l=30752.0 c=30781.25`, an up-close, so there is no OB.
- **Rejection WICK.** The lower wick is 30757.5 − 30752.0 = 5.5 pts of a 31 pt range. That is 0.18, below `REJECTION_WICK_MIN = 0.5`, so there is no wick.
- **FVG/OB with bottom ≤ swept level overlapping the band.** The only FVG is [30701.5, 30710.25], entirely below the band [30747.5, 30801.5], so there is none.

**Sizing would have funded the trade.** The stop is `ote.stopMode=BAND`, which is the intended default per A-04 D6. Sizing already uses that same stop via `plannedStopForSizing`. That stop is 30746.5: the 0.786 edge or the sweep extreme, whichever is further, minus 4 ticks.
- Every entry inside the band costs $2–$110 per micro against a $250 budget, so the sizer would return 2–5 micros.
- The stop is not anchored beyond a range extreme, and NY_AM longs are not unfundable at $250.
- No stop-model change is needed.

**What that would have found on 09-25.** That candle is the 10:05 bar: `o=30803.5 h=30803.5 l=30755.0 c=30757.75`, a down-close that took liquidity into the band. Its body overlaps the band.

- entry = OB mean 30779.25;
- stop = min(0.786 30747.5, OB low 30755.0, sweep 30752.0) − 4 ticks = 30746.5;

## 2. THE FIX: every armed-but-not-emitted path writes its reason and publishes a GateDecisionEvent

**Paths grepped.** I grepped every `return` between OTE_ARMED and `core.tryEmit` in the runner, plus the silent `return false` in the core's `tryEmit`:

| path | before | after (`lastGateFailed` + GateDecisionEvent gate, numberA, numberB) |
|---|---|---|
| `oteDriver.alarm()` false, stall `no-entry-block-14:45-17:00CT` | silent (funnel stall only) | `NO_ENTRY: 14:45-17:00 CT no-entry block (armed, band [lo,hi])`, gate `NO_ENTRY`, close, NaN |
| alarm stall `impulse-no-pd-array-at-sweep` / `no-pd-array-overlapping-band` | silent | `ALARM: … (… swept X overlaps band [lo,hi])`, gate `ALARM`, swept, band lo (or lo, hi) |
| alarm stall `impulse-awaiting-rejection` / `no-reaction-at-band` | silent | `ALARM: …`, gate `ALARM`, swept, lo (or lo, hi) |
| alarm false with no stall (defensive) | silent | `ALARM: not fired (driver gave no stall reason)` |
| tier null (legacy) | `invalidate("no qualifying tier")`, no event | same death reason, plus GateDecisionEvent `TIER` |
| scalp NO-OVERLAP (`positionOpen` / `context.hasPosition`) | silent `return` | `POSITION: MNQ position still open (latch=…, account=…)`, gate `POSITION`, 1/0, 1/0 |
| size ≤ 0 | event only, with `lastGateFailed` left **null** (D-07) | `SIZE: stop too wide for risk budget (need $X/micro, have $Y)`, gate `SIZE`, need $, have $ |
| `core.tryEmit` BIAS safety invariant (emission blocked, current bias not aligned) | silent `return false` in the core | `BIAS: emission blocked (current bias X not aligned with setup Y)` (`// AGENT-05.4` in StdvOteStrategy) |
| `core.tryEmit` validator / SCALP refusal | `lastGateFailed` written, no event | the same reason, plus a GateDecisionEvent (gate = prefix, entry, stop) |
| any other OTE_ARMED end-of-step with `lastGateFailed == null` | possible | backstop `EMIT: armed, attempt produced no signal and no reason` |

**Clearing and publishing.**
- **Self-written.** The runner writes through the new `StdvOteStrategy.writeArmedDiagnostic(reason)`. That sets `gateDiagnosticSelfWritten=true`, so the core clears the reason at the top of the next `tryEmit`.
- **Cleared per attempt.** The runner also clears `ctx.lastGateFailed` at the top of every `tryEmitOrder`, now before the NO-OVERLAP check as well.
- **Retry works.** A later re-plan retries, and M9 is never poisoned. The test proves it: a SIZE deny is followed by a funded retry that emits.
- **Where the reason shows.** `/api/setup` shows it through the runners' `publishSetupDecision`, which is keyed on state|lastGateFailed. The autopsy CSV and the transcript show it too.
- **Publishing.** One GateDecisionEvent is published per distinct reason per armed episode. The dedupe resets when the setup leaves OTE_ARMED or emits.

**Sizer (`StdvOteSizer.riskDerived`).** The rule was already right: floor(budget / $perMicro) clamped to [size.minMicros=1, cap]. It returns ≥ 1 whenever $/micro ≤ budget. Boundary tests pin $249.50 → 1, $250.00 → 1 and $250.50 → deny. The deny text now names the per-micro number: `SIZE: stop too wide for risk budget (need $250.50/micro, have $250.00)`. When minMicros > 1, it reads `need $N = k x $P/micro`. `PropFirmRiskEngine` uses the same function, and its two test strings were updated.

**Harness (test code).**
- The label `OTE_ARMED-sizer-standdown-or-tier` stays, so it can be counted, but it can no longer occur.
- The armed-refusal GateDecisionEvents (SIZE, ALARM, NO_ENTRY, POSITION, TIER, EMIT, BIAS) are written into the signal/order log and the transcript.
