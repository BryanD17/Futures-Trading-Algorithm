## 0. The defect (from the LIVE log)

Account balance $150,620.10, profile Topstep 50K (DLL $1,000, MLL $2,000, riskPerTrade $250, maxContracts 5, target $3,000).

```
[LIFECYCLE] Phase=EVALUATION Zone=CRUISE Target=100.0% DD=0.0% ConsecLoss=0 Budget=$2000 DLLRoom=$1000
[DYNAMIC RISK] Risk=$56.25 (0.112%), zone=CRUISE(0.3x), quality=0.75x
  Reason: RISK: requested 5 micros x $37.00 = $185.00 > risk budget $56.25 (max 1 micros)      (07:00 ET, LTF TIER_3)
[DYNAMIC RISK] BLOCKED: Setup quality 5 < required 7 (zone=CRUISE)                            (09:51 ET, LTF TIER_2)
```

Three causes:
1. **A LIVE-only layer.** LiveEngineRunner ran `PhaseAwareRiskCalculator` and `riskEngine.evaluate(signal, account, limits, dynamicRisk)`. The tape harness (the proof path, R5) ran `riskEngine.evaluate(signal, account, limits)`. What LIVE did was never measured.
2. **Stale sizing budget.** The strategy sized against the static $250 (5 micros), and the risk engine checked against $56.25. So Agent 05's over-budget deny fired where the design intended "requested 1".
3. **Broker balance as zone input.** `lifecycle.syncEquityFromLive(accountState.getEquity())` fed $150,620 against the 50K baseline: +$100K vs a $3K target = 100% = CRUISE at boot.

## 1. The fix

| item | implementation |
|---|---|
| 1. `risk.phaseAware` (default **false**) | Registered in `EngineConfig.KEYS` and `engine-defaults.properties`. The LIVE handler's risk section moved into `risk/LiveRiskPath.evaluate(signal, account, limits, engine)`, which LiveEngineRunner and FunnelAutopsyHarness both call. Both build it with the same factory, `LiveEngineRunner.newLiveRiskPath()` → `LiveRiskPath.topstep50kLive(...)`. **STATIC** (false) = exactly `engine.evaluate(signal, account, limits)` with the static riskPerTrade: no calculator, no quality gate, no zone multiplier. **PHASE_AWARE** (true) = the pre-05.10 LIVE layer unchanged (same calculator, same `RiskProfile.topstep50kEvaluation`, same tier→quality map) followed by `engine.evaluate(..., dynamicRisk)`. |
| Harness models it | The harness builds the same `LiveRiskPath` and feeds the lifecycle where LIVE does: `onCandle` before the execution candle (= `candleHousekeeping`) and `onPositionClosed` from the execution listener (= `notifyPositionClosed`). With `risk.phaseAware=true` it tags each decision `[PHASE_AWARE zone= q= budget= deniedBy=]` and writes a `## Risk path: PHASE_AWARE` section to summary.md. With false it writes nothing new (byte-identical, §3). |
| 2. Size from the effective budget | New `RiskBudgetProvider` plus `StrategyContext.perTradeRiskBudget(symbol, tier, staticRiskPerTrade)`. The default returns the static value. `DefaultStrategyContext` takes an optional provider. `StdvOteRunnerStrategy.riskDerivedSize` (HTF, scalp and LTF machines) and the CT-scalp sizer start from `context.perTradeRiskBudget(symbol, tier, riskPerTrade)` before the unchanged DLL/MLL-room caps and `riskFraction` scaling. The LIVE runner and harness install `livePath.budgetProviderOrNull()`: null when STATIC (the proven path is untouched), and the calculator's dynamic budget for that tier when PHASE_AWARE. If the calculator blocks, the provider returns the static budget and the gate then denies with its own reason. Agent 05's deny-on-over-budget rule stays as the backstop. |
| 3. Zone from tracked P&L | `AccountLifecycle.syncTrackedPnl(pnlSinceStart)`: equity = profile starting balance + (realized + unrealized P&L the engine booked since start). The broker balance is never read. In tracked mode `onDayEnd` no longer re-derives equity from the day-P&L history, and the HWM only moves at day end (Topstep's highest-EOD rule). See §5 for why. `zoneInputs()` gives the zone and every input. `LiveRiskPath.logZone("boot")` runs at boot, and `[LIFECYCLE ZONE] change A -> B: …` is logged on every change. |
| `risk.haltOnProfitTarget` | LIVE default true (the A-05 contract, `RiskConfig.haltOnProfitTarget(true)`). `LiveRiskPath` refuses entries once `PropFirmRiskEngine.hasMetProfitTarget` is met, i.e. **tracked realized P&L since engine start** ≥ target. The broker balance is not used. Deny text: `RISK: profit target reached: tracked realized P&L since engine start $X >= $3000.00 (risk.haltOnProfitTarget=true; broker balance not used)`. SIM keeps its own false default. Neither tape reaches +$3,000, so this changes nothing on the tapes. |
| 4. Boot table | `EngineConfig.modeConsequences()`: `RISK PATH: STATIC (proven) (risk.phaseAware=false) - effective per-trade budget $250.00 (RiskLimits.riskPerTrade), capped by DLL/MLL room \| haltOnProfitTarget=LIVE true / SIM false (tracked P&L since engine start)`, or the PHASE_AWARE formula. The LIVE runner also prints `livePath.bootLine(riskLimits)`: STATIC `$250.00`, or PHASE_AWARE with the live budget per tier (`TIER_4(q9)=$250.00 TIER_3(q7)=$187.50 TIER_2(q5)=$125.00 TIER_1(q3)=BLOCKED[...]`). The "CONVEX PAYOFF OPTIMIZATION: ACTIVE" banner prints only when the layer is on. |

`grep -rn "System.getProperty" trading-engine/src/main` → only `EngineConfigLoader` (javadoc line 18 + lines 88 / 93 / 97).

| 21-day | PHASE_AWARE | 38 | 19 | **19**, all `Setup quality 3 < required 4 (zone=NORMAL)` (TIER_1) | **0** | 17 | 12/5 | **+4.97** | +589.80 | 189.00 | -189.00 | 5 |

- The zone stays **NORMAL** on both tapes. Tracked P&L peaks at +$589.80 (21-day) and +$665.80 (7-day), under the 50% PROTECTION line ($1,500), and the drawdown never reaches 40% of MLL.
- Per-trade budgets: TIER_2 $125 (q5 x 0.5), TIER_3 $187.50, TIER_4 $250.
- What the layer does on this tape: it removes every TIER_1 setup (quality 3 < 4). That is all the counter-HTF / weak-tier LTF and HTF trades. It roughly halves size on TIER_2 (5 → 2-5 micros), and on 09-23 it enforces the profile's 4 trades/day.
- Net result: the 21-day tape gives more R (+4.97 vs +4.10) on fewer, smaller trades, fewer dollars (+$589.80 vs +$884.40), and less than half the drawdown ($189 vs $450). The 7-day tape gives less R (+6.23 vs +8.69) and about half the dollars.
- Envelope intact in every run: DLL / MLL OK, max qty 5, 0 entries in NO_ENTRY/WEEKEND.
- The full per-decision list is in each PA run's summary.md `## Risk path: PHASE_AWARE` section. Each line has the time, tier, quality, zone, budget, requested qty, ALLOW qty or DENY(layer) reason, and tracked P&L.

**Recommendation:** keep `risk.phaseAware=false` for LIVE, which is the proven, measured path and matches the tape byte for byte. Turning it on is now a measured choice (§4). The main effect is the TIER_1 quality gate, which cuts about half the signals on the 21-day tape.

## 5. Findings for Fable

1. **Lifecycle HWM double count (fixed here, in tracked mode).**
   - What happened: the first PHASE_AWARE 21-day run, before the fix, went `NORMAL → CAUTION → DANGER` and phase `FUNDED_PROBATION` on a tape whose tracked P&L never exceeded +$450. The lifecycle HWM read $54,796.80.
   - Cause: `AccountLifecycle.onDayEnd` re-derived equity as `start + Σ dayPnl`, where `dayPnl = account.getNetDailyPnl()` is sampled at the **CT date change**. That is not the 17:00 CT session roll, and the account's day P&L is not reset there, so the history double counts and the HWM inflates.
   - Fix: in tracked mode, equity comes only from the tracked P&L and the HWM moves only at day end. A pre-05.10 LIVE engine running long enough would have hit the same phantom DANGER / FUNDED_PROBATION.
2. **Harness daily P&L never resets (pre-existing, not changed).** In the harness the `AccountState` trading day never rolls, so `getNetDailyPnl()` is cumulative (tape-end `dailyPnL=$1308.30`). The DLL room in the harness's approval strings therefore grows over the tape (`DLL room: $2004.30` on 09-28 in the proven path). This is the same in Main and in 05.10 (byte-identical). It does not change any decision on these tapes, because the per-trade budget ($250) binds before the DLL room. It is an Agent-05 / harness item for Fable.
3. **LIVE today with the default.** After merge and a restart, the 07:00 ET PRAC signal would be approved at 5 micros ($185 ≤ $250) and the 09:51 ET signal at 5 ($190). The boot log will show `RISK PATH: STATIC (proven)` and `[LIFECYCLE ZONE] boot: zone=NORMAL ... trackedPnL=$0.00 ... broker balance NOT used`.
