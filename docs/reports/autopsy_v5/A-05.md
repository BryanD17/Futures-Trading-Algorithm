## TOPSTEP MICRO-CONTRACT RULE

Implemented: **size = floor(riskDollars / (stopTicks × tickValue))**, riskDollars = min(riskPerTrade,
DLL room, MLL room), clamped to **[size.minMicros (1), min(size.maxMicros 20, RiskLimits.maxContracts)]**;
below the floor → DENY `SIZE: stop too wide for risk budget (need $X, have $Y)`; killzone boost after the
risk-derived size, never above the cap. Topstep side: the 50K account's maximum position size is 5
mini-equivalents; micros count 10:1 against it (50 micros). Our hard ceiling of 20 micros per position and
maxTotalContracts 10 (legacy) / 20 (scalp) sit inside that cap.
Sources: Topstep Help Center, "What is the Scaling Plan?" (https://help.topstep.com/en/articles/8284223-what-is-the-scaling-plan);
the 10:1 micro/mini ratio is stated by secondary sources (https://proptradingvibes.com/blog/topstep-maximum-contracts,
https://www.futureshive.com/blog/topstep-scaling-plan-explained). ASSUMPTION: the 10:1 ratio and the
5-contract 50K cap were not verified against the owner's live account settings (API key rejected).
There is no Topstep minimum of 5 micros — the old [5, 20] floor was an engine choice, now `size.minMicros`.

## DECISIONS

1. **Risk engine honours the requested size.** It re-derives with the SAME function
   (`StdvOteSizer.riskDerived`); a request ≤ envelope is honoured as-is; a larger request is REDUCED loudly
   (`[RISK-RESIZE] WARN` + "REDUCED requested N -> M" in the reason) — never silently. Envelope =
   risk-derived × `RiskConfig.maxSizeBoost()` (scalp `scalp.killzoneSizeBoost` ≤ 2.0, legacy 1.0), capped by
   maxContracts, size.maxMicros and the DLL/MLL room. The old "min 1 contract up to 2× budget" exception
   is removed (tightening).
2. **One RR band.** Risk engine enforces the floor only; the 5.0 ceiling lives in the validator (vs the final
   target, Agent 04). Scalp ceiling moves 1.5 → 5.0 (the scalp target is 1R-capped anyway).
3. **size.preferredMicros (5)** is used only when geometry is unknown (no OTE / PD array) — the validator
   rejects such an attempt at M7 anyway. It is never a floor.
4. **Legacy sizing** goes through the same risk-derived path (tier table 18/14/10/6 removed): legacy golden
   fixture quantity 6 → 5 (floor($250/$24) = 10 capped at maxContracts 5); prices/RR unchanged.
5. **RC-16:** the runner subscribes PositionClosedEvent in both modes. Legacy: a release for a signal that never
   executed (no position observed, no trade completed since emission) invalidates the setup → normal legacy
   re-arm; a real closed trade keeps IN_TRADE terminal. The legacy consumer runs inside
   `processLegacyRearm` (active when `stdvOte.rearmOnInvalidated`, default true). M9: `lastGateFailed` is
   cleared at the start of every emit attempt.
6. **Warmup:** completion candle time = max first-live-candle time over required feeds (or, on timeout, the
   newest candle seen). Signals without candleTime (legacy strategies without a dispatcher) fall back to the
   wall-clock creation comparison. LIVE keeps a staleness check, now on the signal's own candle.
7. **SIM order TTL** `order.ttlBars` default = OTE window × 2 = 8 × 5 × 2 = 80 one-minute bars; expiry cancels,
   publishes `ORDER_TTL`, and releases the latch with a synthetic PositionClosedEvent.
8. **Fill race:** `ExecutionEngine.submitOrder(order, stop, target, signalCandleTime)` replays the last ≤5
   candles newer than the signal candle; `activeOrders` lists are CopyOnWriteArrayList; engine methods
   synchronized.
9. **P&L units:** `points / tickSize × tickValue` in ExecutionEngine, Position (so AccountState and the
   api PositionsController are correct too) and LiveEngineRunner.calculatePnl (new `domain/ContractSpecs`).
10. **BracketOrderManager:** stop submission retried 3×; on failure → MARKET flatten through the stop-fill
    funnel + ERROR + `GateDecisionEvent BRACKET`. A failed TP no longer cancels the stop (stop-only
    protection, ERROR + event). Breakeven / qty updates: cancel → re-place (3×) → re-place old level (3×)
    → flatten. LiveEngineRunner's unprotected returns (no bracket manager / invalid bracket prices) →
    emergency MARKET flatten (kill switch if even that fails).
11. **TopstepConnector:** a throwing fill listener keeps the order pending and is retried on the next poll
    (abandoned after 3 with a CRITICAL log + counter); poison bar skipped with ERROR and the watermark
    advances; cancel with HTTP 200 + success=false throws; null-id cancel throws.
12. **News:** `MacroNewsManager.checkTradeGating` is non-blocking when the provider is the Mock or unhealthy
    unless `news.blockWithoutCalendar=true`; every block publishes `GateDecisionEvent NEWS`.
    MarketConditionFilter rejects now carry score + factors.
13. **OrderListener defaults:** `onOrderFilled` / `onOrderRejected` route to `onOrderUpdate` (MockConnector
    fills no longer vanish for lambda listeners). `onOrderCanceled` stays a no-op (TopstepConnector already
    delivers cancels through polling; forwarding would double-notify).
14. **HistoricalBackfill (chart/, not my file) untouched:** a failed backfill chunk can no longer "complete
    warmup" by itself because warmup now requires live candles per feed.
