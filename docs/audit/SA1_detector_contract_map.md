## 2. Per-hook notes and justifications

### 2.1 HTF bias — why `HtfTrendAnalyzer` is the right upgrade target
- `HtfTrendAnalyzer` (strategy/HtfTrendAnalyzer.java) is the designated "Layer 1" directional gate: 15m/30m structure + HH/HL pattern + momentum → 5-state `HtfTrendState` with `allowsDirection(boolean)` and `getSizeMultiplier()`. Refresh cadence: `evaluateTrendState()` runs on every **completed 15m or 30m candle** delivered by `BarAggregationManager.processCandle` (HtfTrendAnalyzer L111–131).
- `MultiTimeframeAnalyzer` supplies the same via `getAlignedHtfBias()` (NEUTRAL unless 30m and 15m agree, L176–181) and is also the validator's HTF-confirmation dependency (`checkHtfConfirmation`, L613–660).
- The 3-of-4 vote (HTF trend / AMD / premium-discount / draw-on-liquidity) has ingredients across `HtfTrendAnalyzer` (`isInFavorableZone` L353–371), `DailyAmdCycleTracker` (`getCurrentPhase()`, `isLongPhase()/isShortPhase()`), and `LiquidityTargetIdentifier.findNextTarget` — but **no existing class implements the vote itself** (see §8.3).

### 2.2 Manipulation leg — candidate comparison (ONE picked)
| Candidate | API | Verdict |
|---|---|---|
| `IctStructureDetector` swings | `getLastSwingHigh()/getLastSwingLow()` | **CHOSEN.** Already wired (runner L340–347), zero new plumbing, LTF-fresh, and the projection engine tolerates a coarse leg (snap tolerance + monotonicity checks in `StdvProjectionEngine`). |
| `DailyAmdCycleTracker` | `getCurrentPhase()`, `getManipulationDirection()`, `getSessionHigh()/getSessionLow()` | Rejected for SA2: its `update(Candle, LevelEngine, …)` is not called anywhere in the runner; phases give manipulation *direction* and session extremes but not the leg's two price extremes as a pair; adding it means new per-bar wiring for marginal gain. Good future input to the §8.1 component. |
| `LevelEngine` session extremes | `getLevel(LevelType)` for ASIA_HIGH/LOW etc. | Rejected: session extremes define *pool locations*, not the manipulation leg itself; the leg is the sweep excursion, which the swing pair approximates more directly. |

### 2.3 Sweep detection mechanics (for SA2's freshness window)
`LiquidityDetector.detectLiquiditySweeps()` (L55–115): looks at the last ≤10 candles' extreme; bullish sweep = `low <= recentLow && close > recentLow` on the latest candle; symmetric for bearish. Sets `lastSweep` (sticky) and `candleCountAtLastSweep`. The runner gates staleness with `hasRecentSweep(3)` (runner L350). `LiquiditySweep` carries `sweptLevel`, `timestamp`, `hasSmtDivergence()` — the SMT flag is computed only if `updateSmt(candle)` has been fed the correlate (runner `onSmtCandle` L199–203 does this).

## 4. Exit-management audit — multi-target assumptions (task 4)

### 4.1 `BracketOrderManager` (execution/BracketOrderManager.java)
- `createBracketWithPartials(symbol, entryOrderId, entryPrice, quantity, entrySide, stopPrice, finalTargetPrice, tier, tickSize)` (L171–341) builds a **TP ladder from `TradeTier.getPartialProfitTargets()`** (TradeTier.java L96–113: e.g. TIER_2 = {1R:50%, 2R:25%, 3R:25%}). Ladder prices are computed from `riskDistance × rMultiple`, **ignoring the signal's target price** except as "finalTargetPrice". With a 1R-target scalp this ladder is wrong: TP2/TP3 would sit beyond the intended exit.
- Special cases already single-TP-friendly: 1 contract → single TP at tier's full R with a 1R price-based breakeven trigger (L205–233, `checkPriceBreakevenTrigger` L722–746); 2 contracts → 1R + runner (L234–261). Irrelevant at 5–20 micros — the standard multi-level branch (L262–296) will engage.
- **Single-TP path that already exists**: legacy `createBracket(symbol, entryOrderId, entryPrice, quantity, entrySide, stopPrice, takeProfitPrice)` (L346–406) — one SL (full qty) + one TP (full qty), OCO both ways, no breakeven logic. **This is how a 1R scalp bracket should be placed** (optionally plus a breakeven trigger). `LiveEngineRunner` already uses exactly this in its fallback path (LiveEngineRunner L267–275).
- OCO semantics: SL fill cancels all TPs (L559–580); all-TP-fill cancels SL (L437–450); first partial fill moves SL to breakeven +2 ticks (L432–434, L461–516).

### 4.2 `TrailingStopManager` (execution/TrailingStopManager.java)
State machine INITIAL → BREAKEVEN → TRAILING keyed off R-multiples from `TradeTierVariant` config (breakeven activation R, trail activation R). For a 1R target the trade will usually resolve before trail activation — harmless but useless; a scalp mode should simply not register positions here, or accept it as dead code per-trade.

### 4.3 `PartialProfitManager` (strategy/PartialProfitManager.java)
`checkPartial(symbol, price, qty, phase, profile)` closes `profile.getPartialExitPct()` at `profile.getPartialExitRMultiple()` (typically 50% @ 1R) and moves stop to BE (L113–165). **With a 1R target this fires at the same price as the full exit** — double-exit / redundant order risk if both are active. Scalp mode must disable partials (`RiskProfile.isPartialsEnabled() == false` path already short-circuits, L116–118).

## 6. Event & Support APIs (task 5)

### 6.1 Order-fill / position-close signals (for SA4 re-arm)
- **EventBus event types exist but are NOT published**: `EventType.java` defines `ORDER_SUBMITTED/FILLED/PARTIALLY_FILLED/CANCELED/REJECTED` (L17–20) and `POSITION_OPENED/UPDATED/CLOSED` (L24–26). `OrderEvent` (event/OrderEvent.java: `getOrder()`, `getFillQuantity()`, `getFillPrice()`) exists. **However**, a repo-wide grep of `eventBus.publish` shows only `StrategySignalEvent` (strategies) and news events (`MacroNewsManager`) are ever published. `EventBus.mapClassToEventType` references `PositionClosedEvent` (EventBus.java L133) but **no such class exists in main**. So SA4 cannot subscribe its way to position-closed today.
- **What actually carries close notifications (callback interfaces, not bus):**
  - `ExecutionEngine.ExecutionListener` (ExecutionEngine.java L38–43): `onPositionOpened(symbol, side, entryPrice, qty)`, `onPositionClosed(symbol, pnl, isWin)`; fired at L462–464 and L538–541; registered via `setExecutionListener` (L101) — `LiveEngineRunner` L248–294 and the backtest runner already register here.
  - `BracketOrderManager.BracketListener` (L127–133): `onStopLossFilled`, `onTakeProfitFilled`, `onPartialTakeProfitFilled`, `onBracketCanceled`, `onStopMovedToBreakeven` — registered in `LiveEngineRunner` L184–240.
- **SA4 options**: (a) smallest: from the runner-level `ExecutionListener.onPositionClosed`, look up the symbol's `StdvOteRunnerStrategy` (via `StdvOteRegistry` or the multi-engine map) and call a new package-private `onPositionClosed()` that marks `DONE` + schedules `resetForNextWindow()`; or (b) cleaner: define a real `PositionClosedEvent` (the EventBus mapping slot already exists) and publish it from `ExecutionEngine`.
- EventBus mechanics: `subscribe(EventType, EventHandler<T>)` or `subscribe(Class<T>, handler)`; async dispatch on 4 worker threads via bounded queue (10k) — handlers run off the candle thread; SA4 re-arm must be thread-tolerant (SetupContext is documented thread-confined, SetupContext.java L17–19 — prefer flag-and-apply-on-next-candle over direct mutation from a handler).

### 6.2 `SilverBulletClock` (strategy/SilverBulletClock.java)
- Windows (ET, `America/New_York`, half-open [start,end)): `LONDON_OPEN` 03:00–04:00, `NY_AM` 10:00–11:00, `NY_PM` 14:00–15:00 (enum L33–37).
- API: `getCurrentWindow(Instant)` : `SilverBulletWindow`; `isInSilverBulletWindow(Instant)`; `getCurrentWindowName(Instant)`; `isOptimalSymbol(String, Instant)` (note: symbol groups list full-size ES/NQ/GC, **not** MNQ/MES/MGC — L61–79, would need mapping); `getMinutesRemaining(Instant)`; `hasEnoughTimeForTrade(Instant)` (≥15 min); `getNextWindowStart(Instant)`; `isTradingDay(Instant)`.

## 8. NEW_COMPONENT_REQUIRED

Everything else has a viable existing source. Three small pure components are genuinely missing:

1. **`ManipulationLegDetector`** (single class, pure function of `CandleSeries` + killzone open time). Current swing-pair approximation works but is not the ICT manipulation leg (Judas swing from session/killzone open). Smallest correct form: given bias and the killzone-open bar index, return `(legLow, legHigh)` = extreme excursion against bias since open, terminated by the reclaim bar. ~60 lines, no state beyond the series. Consumers: `recordManipulationLeg`.
2. **`ImpulseLegTracker`** (single class or ~20 lines inline in the runner). Given the `MSS` object and the `CandleSeries`, return the post-MSS impulse extremes: bullish = (lowest low between sweep bar and MSS bar, highest high since MSS bar), mirrored for bearish. Replaces the stale `getLastSwingHigh/Low` pair in `tryArmOte`. Consumers: `recordOteImpulse`.
3. **`HtfBiasVoter` (3-of-4 rule)** — optional for SA2 first cut. Pure aggregator over four existing booleans: `HtfTrendAnalyzer.allowsDirection`, `DailyAmdCycleTracker.isLongPhase/isShortPhase`, `HtfTrendAnalyzer.isInFavorableZone` (premium/discount), `LiquidityTargetIdentifier.findNextTarget` direction (draw on liquidity). Returns `MarketBias` when ≥3 agree. No new detectors needed — composition only.

Explicitly **not** needed: sweep detector (exists), raid scorer (exists — just call it), FVG-displacement linker (exists inside `DisplacementDetector`), sizer (exists — `StdvOteSizer`), OTE math (exists — `OteEntryCalculator`), position-closed plumbing (exists as `ExecutionEngine.ExecutionListener`; SA4 chooses callback-bridge vs new `PositionClosedEvent`).
